## Core claim

Mesh-LLM pools GPU memory and model-serving capacity across machines and exposes one OpenAI-compatible API, normally at:

`http://localhost:9337/v1`

A request can:

1. run on the local node when the model fits;
2. route across QUIC to a peer already serving the requested model;
3. use Skippy stage splits when the model cannot fit on one machine;
4. fan out to multiple models through the experimental Mixture-of-Agents virtual model.

## Operating modes

- Public mesh discovery through Nostr listings.
- Private meshes joined through invite tokens.
- Requirement-aware meshes with signed bootstrap tokens and immutable policy hashes.
- LAN-only discovery using mDNS.
- API-only clients that consume mesh inference without offering compute.
- Serving nodes that advertise hardware, models, availability, and demand signals.
- Standby nodes that may promote when demand or model availability requires them.

Connectivity uses iroh/QUIC. Managed iroh relay infrastructure is the default fallback when direct paths are unavailable in public/Nostr mode.

## Request routing

Every node exposes the same OpenAI-compatible API. The proxy inspects the requested `model`, then routes to the node elected to host that model.

The system prefers single-machine placement when possible. This avoids stage-to-stage network traffic and gives substantially better throughput.

Current routing features described by the repository include:

- model/capability matching;
- hardware and VRAM awareness;
- tool-capability hard filters;
- request-complexity classification;
- fallback ladders;
- local behavioral health counters;
- prefix affinity;
- demand-aware rebalancing;
- latency-aware split candidate selection.

## Skippy stage splits

For models too large for one node:

1. Resolve an immutable layer-package manifest.
2. Select eligible peers and contiguous layer ranges.
3. Load downstream/final stages first.
4. Publish stage 0 as routable only after the full topology is ready.
5. Send intermediate activation data directly between workers.
6. Preserve the normal OpenAI-compatible endpoint for clients.

Layer packages contain a `model-package.json` manifest and GGUF fragments. Each peer downloads only shared artifacts and the layer files assigned to it. Package and received-artifact hashes can be verified.

Exact topology locks can fail closed on node identity, model ref, manifest digest, and layer ranges.

## Performance reality

The repository's benchmark documentation explicitly warns that numbers are examples rather than universal promises.

For a 17GB GLM-4.7-Flash quantized model on an M4 Max and M4 Mac mini over Wi-Fi:

- solo: 68 tokens/second;
- two-node split: 21 tokens/second;
- three-node split: 12–13 tokens/second.

Cross-network tests around 20ms RTT reportedly produced 10–25 tokens/second, with per-token RPC latency dominating overhead.

The correct interpretation is:

- splitting unlocks models that otherwise cannot run;
- it does not magically aggregate consumer hardware into datacenter-class throughput;
- local full-model serving should be preferred whenever the model fits;
- inter-node latency is a first-order constraint.

## Mixture of Agents

The experimental virtual model `mesh` fans one prompt out to every available model, applies deterministic arbitration, and escalates to a reducer model only on genuine conflict.

The repository labels behavior, heuristics, error shapes, and tuning knobs experimental. This path should not be treated as stable production semantics.

## Identity and trust

Mesh-LLM distinguishes:

- node transport identity;
- owner identity;
- signed owner-to-node attestation;
- release-build attestation.

Owner and node identities remain separate so one owner may operate many nodes and node keys may rotate independently.

Important trust boundary:

- release attestation proves package provenance;
- it does not prove the remote process is unmodified at runtime;
- it does not prove host OS, hardware, model weights, or outputs are trustworthy;
- public mesh behavioral health is local routing evidence, not durable or gossiped reputation.

Public blackboard/plugin content is visible to all peers. The docs explicitly warn against sharing secrets, credentials, private model paths, or customer data on a public mesh.

## Buzz integration evidence

The inspected Buzz source contains actual Mesh-LLM integration rather than only a vision-document mention:

- `mesh-llm-sdk` is used in the Buzz workspace.
- `buzz-relay-mesh` implements relay-side mesh primitives.
- desktop/shared-compute paths start serve or client nodes.
- member-signed Nostr status events advertise owner-bound mesh connectivity.
- nonmembers are denied mesh status through relay membership controls.
- owner allowlists and signed join tokens are used in admission-smoke examples.
- agents are pointed at a local OpenAI-compatible mesh endpoint.

Buzz includes hardware-gated end-to-end tests for trust, serve/client inference, agent inference, and split-model paths. Important caveat: these tests are ignored by default because normal CI lacks multi-node model infrastructure. Some live test rows are runbooks/placeholders rather than continuously exercised acceptance tests. One source comment flags a likely headless console-readiness issue in the desktop Share-compute path.

## Operational caveats

- Experimental distributed-systems software.
- Very large Rust workspace and patched llama.cpp integration.
- Public mesh nodes are outside the operator's full trust boundary.
- Network latency severely affects split inference.
- Model package availability and correct layer splitting are additional operational dependencies.
- Large model downloads and caches consume substantial storage and bandwidth.
- Split stage loss can make the whole topology unavailable.
- Public discovery uses Nostr and managed iroh relay fallback by default.
- Remote runtime integrity is not proven.
- Confidential prompts, customer data, GovCon material, credentials, or private models should remain inside a tightly controlled private mesh with independently validated controls.
