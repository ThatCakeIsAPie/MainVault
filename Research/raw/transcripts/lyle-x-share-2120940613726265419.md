## What log is (from the public repo and docs, retrieved 2026-11-12)

Repo: https://github.com/matthewdonsemail-lab/log
Site: https://log.listeningkit.com
License: MIT. Language: TypeScript. npm package: `@listeningkit/log`.
Repo created: 2026-09-12. At retrieval: about 50 stars, 7 forks, 31 open issues. Latest push on the default branch was 2026-11-12T12:14:54Z (6:14am CT).

log is a local CLI (`log`) and MCP server (`logMcp`). It is meant to read and send from the user's own social accounts — DMs, group chats, replies, notifications, likes, follows, reactions, and voice notes — from a terminal or from an AI agent. The public README's first-class agent setup is Claude Code, Codex, and Cursor. The Hermes path is a separate plugin, described below.

Claimed platform coverage in the README at retrieval:

- X: DMs and X Chat, notifications, followers, replies, posts, likes, follows, lists, reactions, voice notes, queues. Talks to X through "its own API client, one session per account, no browser."
- Discord, Slack, Instagram: live inbox reads and sends (Discord also covers groups and server channels).
- Facebook: Marketplace listings, groups, warm-up, through the account's browser.
- Reddit and LinkedIn: described as "session check (new)" only.

Sign-in is not official OAuth. X, LinkedIn, and Slack are signed in by pasting session cookies. Discord, Reddit, Instagram, and Facebook use a local browser session that log then reuses. Commands that change something are a dry run until `--live` is added. Sessions and a local database live under `~/.logCli`.

The README says the X, Discord, Slack, and Instagram connections were reached by reverse-engineering those platforms' internal APIs, matching the announcement's credit to @treg_ai, @subquadratic, and @morluto. A Hermes catalog validation note on the plugin PR reported an X session using a `directApi (twikit)` engine.

Optional hosted keys named in the README for voice-checking, ranking, and media transcription: SubQ, Jina, AssemblyAI, and Inworld or Fish Audio. Two small models can run on the machine itself (search and image/video-to-text). An optional Twenty CRM is offered for multi-account storage.

Installers are published for macOS, Linux, and Windows (PowerShell). Docs: https://log.listeningkit.com/docs

These product claims were read from the public README, docs, and catalog entry. They were not independently tested here.

## Hermes plugin (from the catalog and plugin README)

Plugin repo: https://github.com/deepmroot/listeningkit-log
Catalog entry: `plugin-catalog/listeningkit-log.yaml` in NousResearch/hermes-agent
Catalog PR: https://github.com/NousResearch/hermes-agent/pull/153834 — merged 2026-11-12T08:26:00Z (2:26am CT, Nov 12) by teknium1, pinned to commit `dd8960d6ab904c351786e1b6ae95ef3c2ad94849`, version 0.1.0.
Requires Hermes `>=0.23.1`. The catalog lists `platforms: [windows]`. Maintainer: deepmroot (Mandeep Singh, @deepman_1, who is also active in this thread).

The plugin does not bundle log. It starts the user's already-installed `logMcp` over stdio and adds two skills (`dm-inbox` and `outreach`). The MCP server is marked `untrusted`, so sends and other writes ask for Hermes approval and are refused in cron and other unattended runs. The plugin README is explicit that the live tool set comes from the installed log version, not from the plugin's pinned commit.

A follow-up catalog PR for version 0.2.0 (a read-only Hermes dashboard tab) was still open at retrieval (https://github.com/NousResearch/hermes-agent/pull/154659). Do not treat that bump as shipped.
