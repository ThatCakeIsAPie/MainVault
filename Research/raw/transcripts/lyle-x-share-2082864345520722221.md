# Lyle X Share — Audio8 versus Kokoro for a local speech edge

## Lyle's note

> This with FasterWhisper might actually be the local play for us. Use Kokoro for TTS and whisper for STT.

## Shared post

Grok's comparison, replying to a question about Audio8 versus Kokoro:

> Audio8-TTS (0.6B) is ~7× larger than Kokoro-82M. It adds zero-shot voice cloning, a 44.1 kHz codec, and 11 languages with strong Seed-TTS scores (EN WER 1.5). Kokoro stays far lighter, faster on CPU, and already delivers high-quality fixed voices across ~8 languages.

The reply points back to Samuel Zeng's Audio8-TTS Preview announcement: 601,159,424 parameters, 11 languages, zero-shot voice cloning, bundled 44.1 kHz codec, and Apache 2.0 licensing.

## Primary-source checks

### Audio8-TTS Preview

- 601,159,424 parameters, excluding codec.
- DualAR autoregressive architecture.
- Eleven recommended languages.
- Zero-shot voice cloning.
- 44.1 kHz bundled codec.
- English Seed-TTS WER 1.506 in the project's comparison.
- Python 3.10+; CUDA-capable GPU recommended.
- Apache 2.0.

Sources:
- https://huggingface.co/Audio8/Audio8-TTS-Preview-0.6b
- https://github.com/Audio8-AI/Audio8_TTS

### Kokoro-82M

- 82 million parameters: roughly one-seventh the size of Audio8's main model.
- Kokoro v1.0 lists eight languages and 54 voices.
- Fixed/prebuilt voices rather than zero-shot voice cloning.
- StyleTTS2 + ISTFTNet decoder architecture; no diffusion.
- Official weights are Apache 2.0.
- `kokoro-onnx` provides CPU support with roughly 300 MB full or 80 MB quantized model packaging.
- Hermes officially supports Kokoro through either an OpenAI-compatible Kokoro server (`tts.openai.base_url`) or a custom command provider.

Sources:
- https://huggingface.co/hexgrad/Kokoro-82M
- https://github.com/thewh1teagle/kokoro-onnx
- https://hermes-agent.nousresearch.com/docs/user-guide/features/tts

## Current-host fit checked 2026-07-30

The Hermes VPS has three AMD EPYC vCPUs, 3.7 GiB RAM, no NVIDIA GPU, ffmpeg, ONNX Runtime, and local faster-whisper installed. Hermes is already configured for local faster-whisper `base`; Kokoro is not yet installed. About 2.0 GiB RAM was available during inspection, with 2.0 GiB swap already occupied.

That makes Kokoro the more credible first local TTS candidate on this host. Audio8's voice cloning and 44.1 kHz output are interesting but unnecessary for Delta's stable personal voice, while its 0.6B autoregressive model and recommended CUDA path add latency and resource pressure.

## Lyle/Delta synthesis

The minimal local speech path is:

> microphone or Telegram voice → faster-whisper `base` → Hermes/Delta → Kokoro-82M → speaker or Telegram voice bubble

This removes cloud STT/TTS dependence while preserving the existing cloud reasoning model, tools, vault, Honcho, and GBrain. “Local” therefore applies to the private speech edge, not yet the full agent brain.

Use a persistent Kokoro service rather than loading the model for every sentence. For Hermes, an OpenAI-compatible Kokoro-FastAPI endpoint is the cleanest supported integration and preserves sentence-level/streaming playback behavior. Benchmark on the VPS first for Telegram output; for the lowest-latency live Desktop experience, the eventual speech service belongs on the machine attached to Lyle's microphone and speakers, reachable privately from Hermes if the backend remains remote.

## Decision rule

Start with Kokoro + faster-whisper because the personal assistant needs low latency, fixed identity, and cheap reliable inference more than voice cloning or studio-rate audio. Revisit Audio8 only if multilingual cloning becomes a real requirement or a GPU-capable edge box removes its latency penalty.
