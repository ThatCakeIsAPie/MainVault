## Experiment described by Cursor

Cursor instructed a new multi-agent swarm to implement the 835-page SQLite manual in Rust. Cursor says it withheld SQLite source code, the SQLite binary, test suites, and internet access. Evaluation used the SQLite project's `sqllogictest`, containing millions of queries with known results. Cursor says the swarm was not told the held-out suite existed and that staff manually reviewed each run for shortcuts and uneven test targeting.

The harness used two recursively organized roles:

- **Planner agents:** frontier models decompose goals, make cross-cutting design decisions, and delegate bounded work.
- **Worker agents:** faster, cheaper models execute narrow leaves of the task tree.

Cursor's thesis is that context separation matters more than raw parallelism: planners avoid low-level implementation noise while workers spend their full context on one bounded task.

## Coordination mechanisms described

- Task decomposition grows recursively around the problem rather than using a fixed swarm topology.
- Planners retain design decisions rather than delegating overlapping architecture.
- Shared design documents reconcile planners' models of reality; dependent code carries compile-checked references back to decisions.
- A neutral third-party agent resolves merge conflicts rather than forcing workers to absorb one another's context.
- Workers can flag “megafiles”; new commits pause while an outside agent decomposes the file into modules.
- Agents are permitted to make focused core changes outside their narrow scope when they document why; compiler failures propagate the decision to dependent work.
- Multiple decorrelated review lenses stack because no single reviewer catches every error.
- Agents maintain a line-budgeted **Field Guide** injected into each new agent, capturing surprises that shorten future trajectories.
- Cursor says the new system uses a custom VCS designed for extreme agent throughput and coordination visibility.

## Results reported by Cursor

These are **vendor-reported results**, not independently reproduced here.

- New harness outperformed old harness in every tested model mix.
- At the four-hour cutoff, new runs reportedly scored **73–85%**, while old runs scored **11–77%**.
- Cursor says every new configuration eventually passed **100%** of the held-out suite.
- The Fable 5 hybrid reportedly passed roughly two-thirds of the suite within its first hour.
- New Grok 4.5 reportedly reached about **80% in four hours**; the old Grok run was paused before two hours due to spiraling coordination.
- Old Grok produced about **68,000 commits in two hours**, roughly 70× the new run's pace, but accumulated more than **70,000 merge conflicts**; the new run logged fewer than 1,000 over four hours.
- Old hottest file: **7,771 conflicts**, touched by **1,173 agents**; new hottest file: **47 conflicts**.
- Old Grok package structure: **54 Rust crates**, including three competing SQL packages; new run stabilized at **nine crates**.
- Fable mix: both old and new eventually passed the suite, but old used **64,305 engine LOC** and new used **9,908**.
- Opus mix: old used **19,013 LOC at 97%**, new used **4,645 LOC at 100%**.
- Named article cost range: **$1,339** for an Opus 4.8 planner + Composer 2.5 worker hybrid versus **$10,565** for GPT-5.5 alone—about 7.9× between those two named runs. The X post's broader headline says model-mix cost varied 15×.
- Workers consumed at least **69% of tokens** and more than 90% in most runs.
- GPT-5.5 workers reportedly cost **$9,373**; Composer 2.5 workers in the Opus hybrid reportedly cost **$411**.

## Source interpretation

The strongest evidence is not “more agents are always better.” It is that **coordination architecture can dominate activity volume**. The old swarm generated vastly more commits and still produced more conflict, duplication, code, and cost.

The economic result depends on both sides of the role split:

1. a capable planner must collapse ambiguity into explicit, non-overlapping work;
2. cheap workers must follow the decomposition without re-opening architectural questions;
3. reconciliation, review, memory, and modularity must be first-class infrastructure.

## Evidence limits

- This is Cursor's own research and product-positioning article.
- The full N×N planner/worker model matrix was not run.
- Exact curves and all model configurations were not independently reproduced here.
- Passing `sqllogictest` is strong functional evidence but not equivalent to SQLite's production maturity, performance, reliability, security, or compatibility.
- Cursor says the public `minisqlite` codebase had received only an initial glance rather than deep manual analysis at publication.
