# GrapheneOS Hardware Diversification (2026)

## Signal

GrapheneOS says its Pixel-only hardware support should begin changing in 2027 through a Motorola Mobility partnership and progress from Qualcomm. The constraint was not brand preference: supported devices must provide the secure-element behavior, hardware-backed exploit mitigations, firmware-update guarantees, and timely updates GrapheneOS treats as minimum security requirements.

## Why this matters

- **Hardware diversity reduces platform concentration.** A privacy-focused operating system tied to one vendor still inherits that vendor's device roadmap and supply constraints.
- **Security requirements remain the gate.** Wider device support is valuable only if new hardware preserves the project's existing threat model; compatibility theater would defeat the point.
- **Upstream influence is leverage.** Getting manufacturers and chip vendors to build required primitives can improve the wider Android hardware market, not merely add another supported handset.

## Faleth take

Treat the announcement as a directional 2027 signal, not a device-buying recommendation yet. The useful pattern is architectural: define non-negotiable security requirements first, then diversify suppliers without weakening them. That is the same procurement logic behind [[faleth/process/zero-data-retention-ai-procurement-control-2026]] and the sovereignty option value in [[faleth/process/local-model-ownership-agency-2026]].

## Open questions

- Which Motorola devices will meet the requirements?
- Will firmware and security-update commitments match Pixel support windows?
- How much of the hardware security stack will be independently auditable?
