## Core moves

| Pattern | Mechanism | Rule of thumb |
|---|---|---|
| Blank forms | Decision fatigue | Every empty field is a tax before value |
| Smart defaults | Trust + reduced choice | Make the good path the easy path |
| Progress not from 0% | Goal-gradient / sunk-start | Start people mid-progress when honest |
| Value before signup | Reciprocity / proof | Extract later; equip first |
| Progress bars | Visible movement | Motivation tracks *felt* progress, not just remaining work |

## Caption anchors

- Blank form feels harder than pre-filled; 0% worse than 20%; signup wall worse than value-first.
- Five empty booking fields = five decisions before anything happens; stack choices → abandon.
- Users often leave smart defaults alone — not laziness, **trust**. Defaults should be the better task.

## Faleth packaging

### CRM / FRR / ops tools
- Intake and vendor forms: **pre-fill what systems already know**; progressive disclosure for advanced fields.
- Don't make techs fill a "blank quiz" to log work already in the system.

### Content / X / recruiting
- **Value-before-signup** is the open-document dojo filter: let the Constitution and frameworks pre-filter believers ∩ builders before the call.
- Onboarding sequences: never open with 0% empty identity; open with a first win.

### LTD / leadership
- Duplication prefers **smart defaults** (the system path) over blank "figure it out."
- Progress bars as belief tools: show people they've already started (first contact, first book, first invite).

### Agency ethics (guardrail)
- These patterns can be used for addiction or for **agency**. Faleth rule: reduce decision load to help people act on purpose, not to hijack them into dependency. Progressive disclosure ≠ dark pattern if exit and honesty stay intact.
